# Implementation status

## Implemented and verified

- Angular 22 editor served by multi-stage Docker image. Tape-sized Fabric canvas, text/images/shapes/backgrounds, IndexedDB gallery, 313 DPI PNG export, cut selection and live print-job polling. Transloco provides English/German UI strings, a persistent language selector, translated print dialog/messages, localized dates and document language/title. Fabric object actions now include Delete/Backspace, Ctrl/⌘+C and Ctrl/⌘+V shortcuts, plus touch-friendly Copy/Paste/Clone buttons. Text editing and form fields keep their native keyboard behavior. Non-printing, draggable cross-tape cut markers are saved per label and split the PNG into sequential print jobs; validation enforces 10 mm per segment and at most 16 segments. The backend waits for printer IDLE between segments and stops on a blocked output slot rather than sending the next segment blindly.
- FastAPI uses an **independent Python implementation of the documented VC-500W XML/TCP wire protocol** (not the Node package). It queries `/config.xml` and `/status.xml`, parses length-delimited replies (including the NUL delimiter observed on the actual device), validates the printer model and tape width, checks IDLE, converts validated PNG to JPEG, sends the vivid-mode XML print command and JPEG only after a success response, closes the socket to trigger the cut cycle, and polls for IDLE. Print jobs expose transmission/stage progress via `/api/jobs/{id}`. Other cassette types and error states have not yet been validated on hardware.
- **Read-only live verification on `192.168.5.225`**: `/connect`, `/tape`, `/status` returned success. The printer reported `Wedge`, firmware `2022071322`, IDLE and no error. Both 25 mm (`cassette_type` `1`) and 12 mm (`cassette_type` `1/2`) adhesive rolls were observed; these are classified as printable only when adhesive and media ID attributes are present.
- Eleven backend tests passed (`python -m pytest backend/test_main.py -q`), including fake-socket byte framing, print rejection before JPEG transmission, cut/size command fields, and asynchronous progress. Angular production build passed. Docker build passed after the protocol update; read-only `/connect` and `/status` requests from the container succeeded against the printer.

## Remaining physical checks

A user successfully printed a label on the supplied printer, but the printer did not return to IDLE within 40 seconds and the original implementation incorrectly marked the print as failed. After a successful JPEG acknowledgement, transmission progress now reaches 100%; the updated code reports `accepted` (not an error or confirmed physical completion) if the printer stays non-IDLE. The browser continues to check for IDLE for up to two minutes while prompting the user to check/remove the label before retrying. Full/half/no cut, ejection sensor behavior, orientation, color and timeout response still need further physical validation. The wire protocol derives from a third-party reverse-engineering reference (credited in `README.md`); firmware variants can differ. Progress during cut is phase-based, not a percent of physical printer motion. See `missing.md`.
