# Remaining requirements and verification

- **Physical print validation:** The source documents XML/TCP print and cut modes, which are now implemented independently and covered by simulated socket tests. A user successfully printed one label on the provided printer. Cut markers now split a design into sequential across-the-tape jobs and are tested with mock printer responses, but a multi-segment physical print has not yet been verified. Check actual spacing/cutter margins, orientation, color and full/half cuts before relying on output; lengthwise cuts are not supported by this printer.
- **Tape and status mapping:** Read-only queries succeed on the supplied 25 mm cassette (numeric cassette code `1` with adhesive metadata) and IDLE state. Other widths, cleaning-tape codes and paper jam/cover open/out-of-tape responses remain unobserved; do not infer them from an unverified code. Unknown tapes are rejected for printing.
- **Progress:** Transmitted byte count is estimated from writes to the OS socket; the printer supplies no physical percent. Completion is reported only after it returns to IDLE after the connection closes. When the JPEG is acknowledged but the printer stays non-IDLE for 40 seconds, the job is marked `accepted` with 100% transmission (not physical completion), since the finished label may be blocking the output sensor. The browser continues to check for IDLE for up to two minutes; check/remove the physical label before retrying to avoid duplicates.
- **Discovery:** Passive mDNS (`_ipp`/`_printer`, host networking only) and an active unicast subnet scan (TCP 9100 + unicast mDNS confirmation, works on a Docker bridge network) are implemented. The scan was tested end to end against a simulated printer from a bridged container; whether the physical VC-500W answers unicast mDNS queries is not yet verified (if not, it is listed as "not confirmed" but can still be selected). Brother-specific UDP broadcasts are not implemented.
- **Editor:** Advanced web-font upload and complex image/SVG features are not included. Raster export and printed bleed/orientation still need physical calibration.
- **Deployment:** Docker build and container read-only requests to the printer succeed locally, but a physical containerized print has not been tested. Multi-arch CI/GHCR publishing is unverified. Only the one-shot `netdetect` sidecar uses host networking; on Docker Desktop set `PRINTER_SCAN_SUBNETS` instead. Restrict the unauthenticated API to a trusted LAN.
